계획한 나와 실제의 나를 비교하는 개인 기록기. 원본 요구사항은 ASSINGMENT.md, 작업 이력은 PROGRESS.md, 5일 실사용 로그는 card5-log.md에 있다. 아래 스크린샷은 "합성 기록 3건 채우기" 또는 직접 입력한 합성(가상) 데이터로 재현했다. 실제 개인 기록(PC 전용)은 포함하지 않는다.

실사용 화면 (한눈에 보기)

카드1을 마친 날부터 서로 다른 실제 날짜 5일(8/27~8/31)간 사용한 화면이다. 기록 8건 + 반복 체크리스트 2건이 남아 있고, 모두 test 태그를 붙인 가상 기록("테스트 1", "게임", "독서", "강의" 등)이다. 8/28에 일부러 심어둔 "초록색" 기록(항목명·표시 색상 불일치)은 5일째에 실제 색상을 초록으로 맞춰 수정한 뒤의 상태다.

  1. 캘린더에서 아무 날짜 칸을 보고, 왼쪽 "기록 추가" 폼에 날짜·항목·값·단위를 입력한 뒤 "추가"를 누른다.
  2. 방금 생긴 칸을 클릭해 상세 모달을 열고 "수정"으로 값을 바꿔 저장하거나 "삭제"를 눌러본다.
  3. 화면 아래 "요약" 영역에서 전체 건수와 주간 요약(항목별 합계)이 방금 한 동작에 맞춰 함께 바뀌는지 확인한다.

무엇이 보이면 통과인가요

  • 추가·수정·삭제 직후 목록(캘린더/테이블) 행과 "요약" 영역의 건수·주간 요약이 같은 화면에서 함께 바뀐다
  • "내보내기·가져오기·전체 삭제" 영역에 세 버튼과, 손상된 파일을 가져올 때 오류 문구가 보인다
  • "주간 요약" 표에 기간(월요일~일요일)과 항목별 합계가 보이고, 잘못된 날짜·값은 별도 "집계에서 제외된 기록" 문구로만 표시된다
  • 화면 어디에도 실제 개인 기록·이름·연락처 같은 정보 없이 합성(가상) 데이터만 보인다

AI 3줄

AI에게 맡긴 일 CRUD·내보내기/가져오기·v1→v2 변환·주간 요약·카드5 개선(기록별 "중요 표시(굵게+★)") 등 app.js/ui.js 구현 전체를 AI에게 맡겼다.
내가 판단한 일 필드 정의, 기준 시간대(Asia/Seoul)·주 시작 요일(월요일), 공개용 데이터는 합성 데이터만 쓴다는 원칙, 그리고 5일 실사용 중 반복된 불편(캘린더·목록에서 어떤 기록이 중요한지 구분이 안 됨)으로 무엇을 고칠지는 직접 정했다.
AI 말을 안 들은 일 날짜 검증에서 AI가 제안한 Date.parse 방식을 쓰지 않았다 — 2026-02-30처럼 존재하지 않는 날짜가 3월로 밀려 통과되는 문제가 있어, 왕복 검증하는 isValidDateString을 직접 만들어 대신 썼다. 카드5에서도 AI가 처음 넣은 "굵게만" 처리로는 눈에 잘 안 띄어, 별 표시(★)·테두리 강조를 더 넣게 했다.

55일 사용 후 한 가지 개선

  • 5일간 서로 다른 실제 날짜(8/27~8/31)에 사용한 로그는 card5-log.md에 있다. 항목은 전부 test 태그를 붙인 가상 기록으로, 실제 개인 기록이 아니다. 캘린더·테이블 화면은 맨 앞 "실사용 화면" 참고.
  • 반복된 불편: 캘린더·목록에서 어떤 기록이 "중요한" 기록인지 구분할 방법이 없었다 → 기록별 "중요 표시(굵게 + ★)" 옵션을 추가했다.
  • 5일째, 8/28에 일부러 심어뒀던 기록 1건(항목명은 "초록색"인데 표시 색상은 어긋나 있던 기록)을 찾아 실제 표시 색상을 초록으로 맞춰 수정했다.

마무리 체크리스트 (최종 검증 기준)

  1. 공개 주소에서 합성 기록을 추가·수정·삭제할 수 있다판단: 공개 화면에서 세 동작 모두 성공 · 증거: origin/main == HEAD(카드5 커밋 3f9568c 포함 전부 푸시됨), 위 카드1 스크린샷
  2. 고유 ID로 정확한 한 건만 수정·삭제된다판단: 동일 항목 여러 건 중 대상 1건만 바뀌고 나머지는 그대로임을 확인 · 증거: Records.update/remove는 항상 id로 대상 탐색 (위 카드1 스크린샷)
  3. 필수값이 빈 기록은 저장되지 않는다판단: 빈 값으로 저장 시도 시 거부됨 · 증거: validateRecordInput(날짜·항목 필수), 위 검증 안내서 "안 될 때" 오류 문구
  4. 새로고침 뒤에도 기록 수와 값이 유지된다판단: 새로고침 전·후 ID·날짜·값이 동일 · 증거: 위 카드2 새로고침 전·후 스크린샷
  5. 내보낸 파일에서 ID·날짜·값·단위가 복원된다판단: 내보내기 → 가져오기 후 원본과 일치 · 증거: ImportExport.exportJSON/parseImport, 위 카드3 v1 가져오기 결과
  6. 전체 삭제 뒤 기록은 0건이다판단: 전체 삭제 실행 후 목록 확인 · 증거: Records.removeAll()
  7. 손상 파일은 기존 기록을 바꾸지 않고 오류 이유를 표시한다판단: 손상 파일 가져오기 시도 시 기존 기록 유지 + 오류 문구 표시 · 증거: 위 카드2 손상 파일 거부 스크린샷
  8. v1·v2 변환 뒤 건수와 기존 값이 유지된다판단: 변환 전·후 ID·날짜·값·단위 대조 일치 · 증거: 위 카드3 스크린샷(fixtures/v1-sample.json 가져오기 결과)
  9. 변환을 두 번 실행해도 기록이 늘거나 다시 바뀌지 않는다(멱등성)판단: 동일 파일로 변환 함수 2회 실행 후 건수·값 비교 · 증거: migrateRecordToV2는 이미 v2면 원본 그대로 반환, Playwright로 변환·재로드 2회 후 값 불변 확인
  10. 주간 요약의 기간과 집계값이 보인다판단: 화면에 기준 시간대·주 시작 요일에 맞는 기간과 합계가 표시 · 증거: 위 카드4·카드5 요약 화면 스크린샷
  11. 잘못된 날짜·값이 집계에서 제외된다판단: 예상 결과표와 실제 집계 결과 일치 · 증거: PROGRESS.md 카드4 예상 결과표 대조, 위 카드4 스크린샷
  12. 실제 개인 기록·개인정보·비밀값이 공개 화면·파일·제출 기록에 0건이다판단: PROGRESS.md "항상 지킬 것" 체크리스트 통과 · 증거: 백엔드 없음(순수 프론트엔드, 비밀값 존재 자체가 불가), 이 문서 스크린샷 전부 합성 데이터·card5-log.md는 날짜·완료 여부만 기록
  13. 검증 안내서가 3단계 이내, 30초 안에 끝난다판단: 어디로/무엇을/통과기준/안될때 4항목 모두 작성, 행동이 3단계 이하 · 증거: 위 "검증 안내서" 섹션
  14. 오너가 공개 결과를 15초 안에 판정할 수 있다판단: 첫 화면만으로 통과 여부가 바로 드러남 · 증거: 위 "실사용 화면" 캘린더·테이블 스크린샷
